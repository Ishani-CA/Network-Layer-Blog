Network layer architecture, functions and internetworking

Article 1, Foundations, 12 min read

On this page

    Introduction

    When you open a website, your request crosses a home router, an ISP, several backbone networks and a data centre before it reaches a server. No single wire connects you to that server, and no machine along the way knows the whole journey. The layer that makes this work is the network layer. Its job is to carry a packet from the source host to the destination host, however many different networks lie between them.

    This article covers what the layer is responsible for, the two ways it can offer service, how unlike networks are joined into one internet, and how tunneling lets one protocol travel inside another.

    Fundamental concepts

    A host is an end device such as a laptop or server. A router is a device with several network connections that forwards packets between them. A packet is the unit of data the network layer handles: a payload from the transport layer plus a network-layer header carrying addresses and control fields.

    Each layer near the bottom has a different idea of delivery:

    LayerDelivers betweenIdentified by
    Data linkTwo directly connected devices (one hop)MAC address
    NetworkSource host and destination host, across many networksIP address
    TransportA process on one host and a process on anotherPort number

    Key idea. The data link layer moves a frame one hop. The network layer strings many hops together into an end-to-end path.

    Detailed explanations

    Design issues

    Designers of the network layer had to settle several questions:

    • The service offered upward. The transport layer should not need to know how many routers exist, what technology links them, or how they are arranged. It sees one uniform address scheme and a simple delivery service.
    • Store-and-forward switching. A router receives a whole packet, checks it, stores it briefly and then sends it on.
    • Connectionless or connection-oriented service. Should packets be routed independently, or should a path be set up first?
    • Addressing. Every host needs a logical address that identifies it and also helps routers decide where to send packets.
    • Routing and forwarding. Routers need a way to learn good paths and a fast way to use them.
    • Differences between networks. Maximum packet sizes, addressing and quality of service vary from network to network.
    • Congestion. Too much traffic at a router must be prevented or relieved (see Article 5).

    Functions and services

    In practice the layer performs these functions: logical addressing, routing (building the paths), forwarding (moving each packet to its next hop), fragmentation and reassembly when a link cannot carry a packet whole, error reporting and diagnostics through ICMP, and congestion control.

    It can offer two kinds of service to the layer above: connectionless and connection-oriented. The next two subsections describe how each is implemented.

    Datagram networks (connectionless service)

    In a datagram network every packet, called a datagram, is treated on its own. Each one carries the full destination address. A router keeps a forwarding table that maps destinations (usually address prefixes) to outgoing links, and it looks up each packet separately. Two packets from the same message can therefore take different paths, arrive out of order, or be lost. The network promises best effort and nothing more. If reliability is needed, the transport layer provides it. The Internet’s IP works this way.

    Virtual-circuit networks (connection-oriented service)

    A virtual-circuit network first runs a set-up phase that picks a path and gives it a short circuit number. Each router on the path records an entry for that circuit. Data packets then carry only the circuit number, follow the chosen path in order, and the circuit is torn down at the end. This keeps per-connection state in every router on the path.

    Internetworking

    The Internet is a collection of separately built networks that differ in many ways: address formats, the largest packet they can carry (the MTU), the protocols they use, and the quality-of-service and security rules they apply. Internetworking joins them. Routers sit at the boundaries, and a common network-layer protocol (IP) runs on top of every network, hiding the differences. When a packet is larger than the next network’s MTU, the router splits it into fragments that are reassembled at the destination.

    Direct and indirect delivery

    A sender first asks one question: is the destination on my own network?

    • Direct delivery: the destination is on the same network, so the packet goes straight to that host at the link layer.
    • Indirect delivery: the destination is on a different network, so the packet is sent to a router (the default gateway), which forwards it hop by hop. Every delivery ends with direct delivery on the last network, from the final router to the destination host.

    Tunneling

    Sometimes two networks of the same type must communicate across a different type of network in between, for example two IPv6 networks connected through an IPv4-only network. With tunneling, the router at the tunnel entrance wraps the entire IPv6 packet as the payload of an IPv4 packet. The IPv4 network forwards it like any other packet. The router at the exit removes the outer header and delivers the original IPv6 packet.

    Working principles and processes

    Store-and-forward at one router

    1. The packet arrives and is received completely on the incoming link.
    2. The router checks it for damage (in IPv4, by verifying the header checksum).
    3. It looks up the destination in its forwarding table to find the outgoing link.
    4. The packet waits in that link’s queue until the link is free.
    5. It is transmitted to the next hop.

    A datagram crossing the network

    Packet to 203.0.113.7 arrives at R1
R1 lookup: 203.0.113.0/24 -> link 2, next hop R3
R3 lookup: 203.0.113.0/24 -> link 3, next hop R4
R4: network 203.0.113.0/24 is directly connected, deliver to host

    No router knows the whole path. Each makes one local decision.

    Practical examples and worked problems

    Problem 1: store-and-forward delay

    A 12,000-bit packet crosses three links, each 1 Mbps, through two routers. Ignore propagation and queuing delay. How long does it take?

    Each link needs 12,000 / 1,000,000 = 12 ms to transmit the packet. A router must receive the whole packet before sending it on, so the transmissions happen one after another: 3 × 12 ms = 36 ms.

    Problem 2: direct or indirect delivery?

    A host at 192.168.1.10 with mask 255.255.255.0 and default gateway 192.168.1.1 sends to (a) 192.168.1.50 and (b) 192.168.2.5.

    The sender’s network is 192.168.1.0/24. For (a), the destination is in the same network, so delivery is direct. For (b), 192.168.2.5 lies in 192.168.2.0/24, a different network, so delivery is indirect: the packet goes to the gateway 192.168.1.1.

    Problem 3: tunnel overhead

    An IPv6 packet of 1,500 bytes enters an IPv4 tunnel that adds a 20-byte outer header. The tunnel links have an MTU of 1,500 bytes.

    The encapsulated packet is 1,500 + 20 = 1,520 bytes, which is larger than the MTU. It must be fragmented, or the inner packet must be limited to 1,500 − 20 = 1,480 bytes. This is why tunnels often lower the usable packet size.

    Real-world applications

    • The Internet. IP is a datagram service, so each packet you send is routed independently.
    • Provider backbones. Carriers use MPLS, which forwards by short labels along paths set up in advance, much like virtual circuits.
    • VPNs. A VPN tunnels your private traffic through the public Internet, wrapped inside outer packets.
    • IPv6 transition. Configured tunnels carry IPv6 across IPv4-only parts of the network.
    • Your home router. It is your default gateway, so every packet to another network is indirect delivery through it.

    Tunneling lets networks interconnect without changing the networks in between, but it adds header overhead, lowers the usable packet size, and makes troubleshooting harder because the real packet is hidden inside another.

    Key takeaways

    • The network layer delivers packets host to host across many networks, using logical addresses.
    • Routers use store-and-forward switching and decide hop by hop.
    • Datagram service routes each packet independently, while virtual circuits set up a path first.
    • Internetworking joins different networks through routers and a common protocol, IP.
    • A sender uses direct delivery on its own network and indirect delivery through a router otherwise.
    • Tunneling carries one protocol’s packets inside another’s.

    Check your understanding

    Question 1

    A host at 10.0.0.5/24 sends a packet to 10.0.0.77. What kind of delivery is used?

    Both addresses are in 10.0.0.0/24, so the destination is on the sender’s own network and the packet is delivered directly.

    Question 2

    Which statement describes a datagram network?

    Datagram routers keep only a forwarding table and treat every packet separately, so packets can take different paths and arrive out of order.
