Routing algorithms and techniques

Article 2, Routing, 25 min read

On this page

    Introduction

    Picture a router with five links and a packet addressed to a host on the other side of the world. The router has to decide which of its five links the packet should leave on. It cannot ask anyone, and it cannot see the whole Internet. It can only look at its own table and choose. Everything in this article is about how that table gets its entries, and how the entries stay correct when links fail and traffic changes.

    We start with one simple principle about shortest paths, then build up to the three families of routing used on the real Internet: distance vector, link state and path vector. Along the way you will step through the algorithms yourself, see the actual bytes that real routing messages are made of, and meet the classic failure that every distance vector protocol has to guard against.

    Fundamental concepts

    Routing is the work of building and maintaining the routing table. Forwarding is the work of using that table to move one packet to its next hop. Routing happens in the background every few seconds or minutes. Forwarding happens for every single packet, in microseconds. Article 3 covers forwarding in detail.

    A good routing method should be correct, simple, robust when links or routers fail, stable (it settles on an answer instead of changing its mind constantly), fair, and efficient. These goals often pull against each other, which is why several different methods exist.

    Static and dynamic routing

    With static routing (also called non-adaptive routing), an administrator types each route into each router by hand. It costs nothing while running, uses no network bandwidth for routing messages, and behaves predictably. Its weakness is that it cannot react: if a link fails, packets keep being sent into it until a person notices and edits the table. Static routing is a good fit for small networks and for a single default route that points toward an Internet Service Provider.

    With dynamic routing (adaptive routing), routers exchange information using a routing protocol and recompute their tables automatically. The network heals itself, but the routers spend memory, processing time and bandwidth to do it.

    Autonomous systems, intradomain and interdomain routing

    An Autonomous System (AS) is a group of networks and routers controlled by a single administration, such as a university, a company or an Internet Service Provider. Routing inside one autonomous system is called intradomain routing, and routing between autonomous systems is called interdomain routing. Splitting the problem this way keeps routing tables small and lets each organisation choose its own internal rules without telling the world.

    Key idea. The routing protocols fall into three families. Intradomain protocols use distance vector (Routing Information Protocol, RIP) or link state (Open Shortest Path First, OSPF). Interdomain routing uses path vector (Border Gateway Protocol, BGP).

    Detailed explanations

    The optimality principle and the sink tree

    The optimality principle says that if router J lies on the best path from router I to router K, then the best path from J to K follows exactly the same route. It sounds obvious, but it has a powerful consequence. If you collect the best path from every router to one particular destination, the paths merge into a tree rooted at that destination, called the sink tree (or shortest path tree). A tree has no loops, so following the best paths can never send a packet round in circles.

    Every algorithm in this article is really a method for discovering the sink tree, or a router’s own view of it, using only local information.

    Shortest path routing: Dijkstra’s algorithm

    If a router has a complete map of the network with a cost on every link, it can compute the cheapest path to every other router using Dijkstra’s algorithm. The algorithm keeps two lists. The tentative list holds nodes whose cheapest cost found so far might still improve. The permanent list holds nodes whose cheapest cost is final.

    At each step it takes the node with the lowest cost from the tentative list and makes it permanent. Then it looks at that node’s neighbours. If a neighbour is new, it joins the tentative list. If it is already there but the new route is cheaper, the cost is replaced. The algorithm stops when the tentative list is empty. You can run it step by step in the first demonstration below.

    Flooding

    Flooding is the simplest method of all. A router copies every incoming packet onto every link except the one it arrived on. It needs no map and no table, it always finds the shortest path (because it tries every path at once), and it keeps working even when much of the network is destroyed.

    The price is an enormous number of duplicates. Two controls keep it manageable. A hop counter in the packet header is reduced at every router and the packet is discarded when it reaches zero. Alternatively, sequence numbers let each router remember which packets it has already forwarded and ignore repeats. Flooding is used to spread link state information (described below), and in military and wireless networks where robustness matters more than efficiency.

    Distance vector routing

    In distance vector routing, each router keeps a table with one row per destination, showing the best known cost and the next router to use. At the start, a router knows only itself (cost 0) and its directly connected neighbours (the cost of the link). Every other destination is marked as infinite.

    Each router then shares its whole table with its immediate neighbours, and only with them. This happens periodically, and also immediately whenever something changes. When a table arrives from neighbour N, the receiving router adds the cost of the link to N to every cost in the table, and compares the results with its own entries. If the route through N is cheaper, or the destination was unknown, the router replaces its entry and records N as the next router. This is the Bellman-Ford method. Over several rounds of exchange, good routes spread through the whole network.

    Two-node and three-node instability

    Distance vector has a serious weakness: good news travels fast, but bad news travels slowly. Imagine a network X connected to router A, which is connected to router B. B reaches X through A. Now the link between X and A breaks. A immediately knows X is unreachable, but before A can tell B, B’s regular update arrives, saying B can reach X at a small cost. A believes it, and adds the cost of the A-to-B link, concluding that X is reachable through B. In reality B’s route goes through A. The two routers now pass the route back and forth, each raising the cost, in a loop that stops only when the cost reaches the protocol’s value for infinity. This is called two-node instability. The same thing can happen around a loop of three routers, called three-node instability. You can watch it happen in the second demonstration below.

    Several remedies exist. Defining infinity as a small number (16 in RIP) means the counting stops quickly. Split horizon says a router never sends a route back out of the interface it learned it from. In the example, B would not tell A about X, because B learned X from A. Poison reverse is a stronger version: B does tell A about X, but with the cost set to infinity, so A is told clearly that B has no independent route. Triggered updates make routers announce bad news immediately instead of waiting for the next periodic update. Split horizon fixes two-node instability but not every loop through three or more routers, which is why these techniques are combined.

    Link state routing

    Link state routing takes the opposite approach to distance vector. Instead of sharing its table, each router shares what it knows first-hand: the state of its own links. Every router then holds a complete picture of the network and computes its own routes from it.

    The process has five steps. First, each router discovers its neighbours by sending small greeting packets. Second, it measures the cost of the link to each neighbour. Third, it builds a link state packet listing its neighbours and those costs. Fourth, it floods that packet to every router in the network, and every router does the same. Fifth, each router now has the same map, runs Dijkstra’s algorithm with itself as the root, and builds its shortest path tree and routing table. Because every router works from the same map, loops are far less likely, and the network reacts to a failure as soon as the new link state packet has been flooded.

    Path vector routing

    Between autonomous systems, the cheapest path is often not the one that is wanted. Business agreements decide who may carry whose traffic, and organisations do not want to share their internal maps. Path vector routing solves this. For every destination, a router keeps not a cost but the list of autonomous systems that the path will cross. When it passes a route on, it adds its own AS number at the front of the list.

    This gives loop prevention for free. If a router receives a path that already contains its own AS number, it ignores the announcement, because accepting it would create a loop. And since the receiver sees which systems are on the path, it can apply policy: for example, refuse any path through a competitor, or prefer a cheaper provider.

    Why routing protocols are needed

    Imagine a company with 50 routers and 200 networks. With static routing, an administrator would type every route into every router, and when a link failed, someone would have to find the fault and edit tables by hand while users waited. A routing protocol automates all of this. Routers find their neighbours, share what they can reach, choose the best path, and switch to an alternative when a link dies.

    Protocols are grouped by where they run. An Interior Gateway Protocol (IGP), such as RIP or OSPF, works inside one autonomous system. An Exterior Gateway Protocol (EGP), in practice BGP, works between autonomous systems.

    RIP: the Routing Information Protocol

    What it is. RIP is a distance vector protocol for use inside an autonomous system. Its cost, called the hop count, is the number of networks a packet must cross to reach the destination, where a directly connected network counts as 1. A hop count of 16 means unreachable, so RIP only suits networks no more than 15 hops across. RIP has two message types, request and response. Routers send a response containing their routing table to their neighbours every 30 seconds, using User Datagram Protocol (UDP) port 520, and they discard a route that has not been refreshed for about 180 seconds. RIP version 2 includes subnet masks, so it works with classless addressing, and sends its updates to the multicast address 224.0.0.9.

    Why it exists. RIP is very simple. It needs almost no configuration, uses little memory, and is easy to understand and to debug. For a small network, that is exactly what is wanted.

    Example. A small office has three routers in a row: R1, R2 and R3. R1’s own network is 10.0.1.0/24, R2’s is 10.0.2.0/24 and R3’s is 10.0.3.0/24. (The /24 means the first 24 bits of the address identify the network.) Once RIP has settled, R1 lists 10.0.1.0/24 at 1 hop (directly connected), 10.0.2.0/24 at 2 hops through R2, and 10.0.3.0/24 at 3 hops through R2. If R3 is switched off, R2 stops hearing from it, and after the 180-second timeout R2 removes the route to 10.0.3.0/24, and R1 follows at its next update.

    Weaknesses. The 15-hop limit, slow convergence, the count-to-infinity problem, and a cost that ignores how fast each link is.

    OSPF: Open Shortest Path First

    What it is. OSPF is a link state protocol for use inside an autonomous system. Every router builds a map of its area from link state information and runs Dijkstra’s algorithm on it. The cost of a link is configurable and is usually derived from its bandwidth, so faster links cost less. OSPF messages are carried directly inside Internet Protocol (IP) packets, not inside UDP or TCP. Routers find neighbours with Hello packets, typically every 10 seconds, sent to the multicast address 224.0.0.5. The five packet types are Hello, Database Description, Link State Request, Link State Update and Link State Acknowledgment.

    Why it exists. RIP could not cope with large networks: its 15-hop limit, slow convergence and indifference to link speed were all serious problems. OSPF scales by dividing an autonomous system into areas. Every area connects to a special central area, the backbone (area 0). A change inside one area is flooded only inside that area, so the rest of the network is spared.

    Areas and router roles. A backbone router sits in area 0. An area border router connects an area to the backbone and summarises that area for the others. An autonomous system boundary router connects the whole autonomous system to other autonomous systems.

    Link types. OSPF describes the network as a graph and recognises four kinds of link. A point-to-point link joins exactly two routers. A transient link is a shared network, such as an Ethernet segment with several routers on it; to avoid every router being linked to every other, one router is elected as the designated router and represents the network. A stub link is a dead end, a network attached to only one router. A virtual link is one an administrator creates to repair the backbone when a link breaks, using a longer path through other routers.

    Weaknesses. OSPF needs more memory and processing power than RIP, and more planning (areas, router identifiers).

    BGP: the Border Gateway Protocol

    What it is. BGP (version 4 is in use today) is the path vector protocol that connects autonomous systems into the Internet. Two BGP routers form a session over a Transmission Control Protocol (TCP) connection on port 179 and exchange announcements, each stating that an address block can be reached through a given list of autonomous systems. A session between routers in different autonomous systems is an External BGP (E-BGP) session. A session between routers in the same autonomous system is an Internal BGP (I-BGP) session, used to carry what was learned from outside to every router inside. BGP has four message types: Open, Update, Keepalive and Notification.

    Why it exists. The Internet is thousands of independent networks. They must tell each other which addresses they can reach, but they do not want to reveal their internal maps, and they want to apply business rules, such as preferring a cheaper provider or refusing to carry a competitor’s traffic. Distance alone cannot express that, so BGP chooses routes by policy first, and uses the shortest AS path to break ties.

    Example. A company (AS 64498) owns the address block 203.0.113.0/24 and buys service from an ISP (AS 64497). The company announces the block to the ISP with the path 64498. The ISP puts its own number in front and announces it to a larger provider (AS 64496) with the path 64497 64498. The provider now knows how to reach the company (Figure 2). Any BGP router that sees its own AS number inside a path ignores the announcement, so announcements cannot loop.

    Weaknesses. BGP is complex to configure, can converge slowly, and largely trusts what its neighbours announce, so a mistaken or false announcement can misdirect traffic.

    Working principles and processes

    Dijkstra’s algorithm

    1. Set the root to the local node and place it on the tentative list with cost 0.
    2. If the tentative list is empty, stop.
    3. Move the tentative node with the lowest cost to the permanent list.
    4. For each neighbour of that node that is not yet permanent, add it to the tentative list with cost (node cost + link cost). If it is already tentative with a higher cost, replace that cost and record the new route.
    5. Go back to step 2. When finished, follow the recorded routes back from each node to find its next router.

    One distance vector update

    1. A table arrives from a neighbour.
    2. Add the cost of the link to that neighbour to every cost in the table.
    3. For each destination, if the new cost is lower than the current entry, or the destination is new, replace the entry and set the next router to that neighbour.
    4. If any entry changed, send the updated table to the neighbours.

    Problem 2: distance vector tables and an update at A

    At the start, A knows only its neighbours: A 0, B 5, C 2, D 3, E unknown (infinite). C’s initial table is A 2, B 4, C 0, D infinite, E 4. When C’s table reaches A, A adds the cost of the A–C link (2) to every entry: A 4, B 6, C 2, D infinite, E 6. Comparing with its own table, A keeps B at 5 (5 is less than 6) and D at 3, but E was unknown, so A records E at cost 6 through C.

    After all routers have exchanged tables several times, the tables stop changing. Each entry shows the cost, with the next router in brackets (a dash means directly connected):

    Problem 3: two-node instability with real numbers

    Network X connects to A at cost 2, and A connects to B at cost 4. Before the failure, A reaches X at 2, and B reaches X at 4 + 2 = 6 through A. The X–A link fails.

    A: X unreachable (infinity)       B: X = 6 via A
B sends its table to A:  A hears X = 6, records 4 + 6 = 10 via B
A sends its table to B:  B hears X = 10, records 4 + 10 = 14 via A
B sends its table to A:  A records 4 + 14 = 18 via B
...and so on, each exchange adding 4

    With split horizon, B never sends X to A (it learned X from A), so A keeps X as unreachable and the loop never begins.

    Problem 4: RIP or OSPF, which path is chosen?

    A router can reach a server by two paths. Path 1 crosses 2 links of 10 Mbps (megabits per second) each. Path 2 crosses 3 links of 100 Mbps each. Let the OSPF cost of a link be 100 Mbps divided by its speed, so a 10 Mbps link costs 10 and a 100 Mbps link costs 1.

    RIP counts hops, so it picks Path 1 (2 hops against 3), which is the slow route. OSPF adds the costs: Path 1 is 10 + 10 = 20 and Path 2 is 1 + 1 + 1 = 3, so it picks the faster Path 2.

    Real-world applications

    RIP still appears in small office networks and teaching labs because it takes only a few commands to switch on. OSPF is widely used inside companies, universities and ISP networks, where a quick reaction to a failed link matters. BGP holds the Internet together: every ISP and large organisation uses it to announce its address blocks to its neighbours, and a configuration mistake in BGP has, on more than one occasion, taken large services offline for hours.

    Static routes are common at the edge. The router in your home has a single default route that points to your ISP. And flooding underlies the way OSPF routers share their link state packets.

    Key takeaways

    • Routing builds the table, and forwarding uses it for every packet.
    • The optimality principle means the best paths to one destination form a sink tree, which has no loops.
    • Dijkstra’s algorithm computes shortest paths from a complete map using a tentative list and a permanent list.
    • Distance vector shares tables with neighbours. It can count to infinity, and split horizon, poison reverse and triggered updates reduce the problem.
    • Link state floods link information so every router can run Dijkstra on the same map.
    • Path vector (BGP) carries lists of autonomous systems, which allows policy and prevents loops.
    • RIP and OSPF run inside an AS, and BGP runs between ASes.

    Check your understanding

    Question 1

    How does split horizon help a distance vector protocol?

    Withholding a route from the neighbour it came from stops two routers from feeding each other stale information, which is what drives two-node count to infinity.

    Question 2

    In the lecture network, what is the cost of the shortest path from A to E?

    A to C costs 2 and C to E costs 4, giving 6. The route through B costs 5 + 3 = 8. D is not on a path to E at all.

    Question 3

    Which transport does BGP use for its messages?

    BGP runs over a TCP connection on port 179, which gives it reliable delivery. RIP uses UDP port 520, and OSPF runs directly inside IP.
